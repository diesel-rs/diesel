3//! A multi-producer, multi-consumer channel that only retains the *last* sent
4//! value.
5//!
6//! This channel is useful for watching for changes to a value from multiple
7//! points in the code base, for example, changes to configuration values.
8//!
9//! # Usage
10//!
11//! [`channel`] returns a [`Sender`] / [`Receiver`] pair. These are the producer
12//! and consumer halves of the channel. The channel is created with an initial
13//! value.
14//!
15//! Each [`Receiver`] independently tracks the last value *seen* by its caller.
16//!
17//! To access the **current** value stored in the channel and mark it as *seen*
18//! by a given [`Receiver`], use [`Receiver::borrow_and_update()`].
19//!
20//! To access the current value **without** marking it as *seen*, use
21//! [`Receiver::borrow()`]. (If the value has already been marked *seen*,
22//! [`Receiver::borrow()`] is equivalent to [`Receiver::borrow_and_update()`].)
23//!
24//! For more information on when to use these methods, see
25//! [here](#borrow_and_update-versus-borrow).
26//!
27//! ## Change notifications
28//!
29//! The [`Receiver`] half provides an asynchronous [`changed`] method. This
30//! method is ready when a new, *unseen* value is sent via the [`Sender`] half.
31//!
32//! * [`Receiver::changed()`] returns:
33//!     * `Ok(())` on receiving a new value.
34//!     * `Err(`[`RecvError`](error::RecvError)`)` if the
35//!       channel has been closed __AND__ the current value is *seen*.
36//! * If the current value is *unseen* when calling [`changed`], then
37//!   [`changed`] will return immediately. If the current value is *seen*, then
38//!   it will sleep until either a new message is sent via the [`Sender`] half,
39//!   or the [`Sender`] is dropped.
40//! * On completion, the [`changed`] method marks the new value as *seen*.
41//! * At creation, the initial value is considered *seen*. In other words,
42//!   [`Receiver::changed()`] will not return until a subsequent value is sent.
43//! * New [`Receiver`] instances can be created with [`Sender::subscribe()`].
44//!   The current value at the time the [`Receiver`] is created is considered
45//!   *seen*.
46//!
47//! ## [`changed`] versus [`has_changed`]
48//!
49//! The [`Receiver`] half provides two methods for checking for changes
50//! in the channel, [`has_changed`] and [`changed`].
51//!
52//! * [`has_changed`] is a *synchronous* method that checks whether the current
53//!   value is seen or not and returns a boolean. This method does __not__ mark the
54//!   value as seen.
55//!
56//! * [`changed`] is an *asynchronous* method that will return once an unseen
57//!   value is in the channel. This method does mark the value as seen.
58//!
59//! Note there are two behavioral differences on when these two methods return
60//! an error.
61//!
62//! - [`has_changed`] errors if and only if the channel is closed.
63//! - [`changed`] errors if the channel has been closed __AND__
64//!   the current value is seen.
65//!
66//! See the example below that shows how these methods have different fallibility.
67//!
68//! ## [`borrow_and_update`] versus [`borrow`]
69//!
70//! If the receiver intends to await notifications from [`changed`] in a loop,
71//! [`Receiver::borrow_and_update()`] should be preferred over
72//! [`Receiver::borrow()`].  This avoids a potential race where a new value is
73//! sent between [`changed`] being ready and the value being read. (If
74//! [`Receiver::borrow()`] is used, the loop may run twice with the same value.)
75//!
76//! If the receiver is only interested in the current value, and does not intend
77//! to wait for changes, then [`Receiver::borrow()`] can be used. It may be more
78//! convenient to use [`borrow`](Receiver::borrow) since it's an `&self`
79//! method---[`borrow_and_update`](Receiver::borrow_and_update) requires `&mut
80//! self`.
81//!
82//! # Examples
83//!
84//! The following example prints `hello! world! `.
85//!
86//! ```
87//! use tokio::sync::watch;
88//! use tokio::time::{Duration, sleep};
89//!
90//! # async fn dox() -> Result<(), Box<dyn std::error::Error>> {
91//! let (tx, mut rx) = watch::channel("hello");
92//!
93//! tokio::spawn(async move {
94//!     // Use the equivalent of a "do-while" loop so the initial value is
95//!     // processed before awaiting the `changed()` future.
96//!     loop {
97//!         println!("{}! ", *rx.borrow_and_update());
98//!         if rx.changed().await.is_err() {
99//!             break;
100//!         }
101//!     }
102//! });
103//!
104//! sleep(Duration::from_millis(100)).await;
105//! tx.send("world")?;
106//! # Ok(())
107//! # }
108//! ```
109//!
110//! Difference on fallibility of [`changed`] versus [`has_changed`].
111//! ```
112//! use tokio::sync::watch;
113//!
114//! # #[tokio::main(flavor = "current_thread")]
115//! # async fn main() {
116//! let (tx, mut rx) = watch::channel("hello");
117//! tx.send("goodbye").unwrap();
118//! drop(tx);
119//!
120//! // `has_changed` does not mark the value as seen and errors
121//! // since the channel is closed.
122//! assert!(rx.has_changed().is_err());
123//!
124//! // `changed` returns Ok since the value is not already marked as seen
125//! // even if the channel is closed.
126//! assert!(rx.changed().await.is_ok());
127//!
128//! // The `changed` call above marks the value as seen.
129//! // The next `changed` call now returns an error as the channel is closed
130//! // AND the current value is seen.
131//! assert!(rx.changed().await.is_err());
132//! # }
133//! ```
134//!
135//! # Closing
136//!
137//! [`Sender::is_closed`] and [`Sender::closed`] allow the producer to detect
138//! when all [`Receiver`] handles have been dropped. This indicates that there
139//! is no further interest in the values being produced and work can be stopped.
140//!
141//! The value in the channel will not be dropped until all senders and all
142//! receivers have been dropped.
143//!
144//! # Thread safety
145//!
146//! Both [`Sender`] and [`Receiver`] are thread safe. They can be moved to other
147//! threads and can be used in a concurrent environment. Clones of [`Receiver`]
148//! handles may be moved to separate threads and also used concurrently.
149//!
150//! [`Sender`]: crate::sync::watch::Sender
151//! [`Receiver`]: crate::sync::watch::Receiver
152//! [`changed`]: crate::sync::watch::Receiver::changed
153//! [`has_changed`]: crate::sync::watch::Receiver::has_changed
154//! [`borrow`]: crate::sync::watch::Receiver::borrow
155//! [`borrow_and_update`]: crate::sync::watch::Receiver::borrow_and_update
156//! [`Receiver::changed()`]: crate::sync::watch::Receiver::changed
157//! [`Receiver::borrow()`]: crate::sync::watch::Receiver::borrow
158//! [`Receiver::borrow_and_update()`]:
159//!     crate::sync::watch::Receiver::borrow_and_update
160//! [`channel`]: crate::sync::watch::channel

162//! [`Sender::closed`]: crate::sync::watch::Sender::closed

217/// Returns a reference to the inner value.
218///
219/// Outstanding borrows hold a read lock on the inner value. This means that
220/// long-lived borrows could cause the producer half to block. It is recommended
221/// to keep the borrow as short-lived as possible. Additionally, if you are
222/// running in an environment that allows `!Send` futures, you must ensure that
223/// the returned `Ref` type is never held alive across an `.await` point,
224/// otherwise, it can lead to a deadlock.
225///
226/// The priority policy of the lock is dependent on the underlying lock
227/// implementation, and this type does not guarantee that any particular policy
228/// will be used. In particular, a producer which is waiting to acquire the lock
229/// in `send` might or might not block concurrent calls to `borrow`, e.g.:
230///
231/// <details><summary>Potential deadlock example</summary>
232///
233/// ```text
234/// // Task 1 (on thread A)    |  // Task 2 (on thread B)
235/// let _ref1 = rx.borrow();   |
236///                            |  // will block
237///                            |  let _ = tx.send(());
238/// // may deadlock            |
239/// let _ref2 = rx.borrow();   |
240/// ```
241/// </details>

    #[inline]
    #[rustc_trivial_field_reads]

        ::core::fmt::Formatter::debug_struct_field2_finish(f,
            "Ref inner has_changed", &self.inner, &&self.has_changed)

}Debug)]

249    /// Indicates if the borrowed value is considered as _changed_ since the last
250    /// time it has been marked as seen.
251    ///
252    /// Unlike [`Receiver::has_changed()`], this method does not fail if the channel is closed.
253    ///
254    /// When borrowed from the [`Sender`] this function will always return `false`.
255    ///
256    /// # Examples
257    ///
258    /// ```
259    /// use tokio::sync::watch;
260    ///
261    /// # #[tokio::main(flavor = "current_thread")]
262    /// # async fn main() {
263    /// let (tx, mut rx) = watch::channel("hello");
264    ///
265    /// tx.send("goodbye").unwrap();
266    /// // The sender does never consider the value as changed.
267    /// assert!(!tx.borrow().has_changed());
268    ///
269    /// // Drop the sender immediately, just for testing purposes.
270    /// drop(tx);
271    ///
272    /// // Even if the sender has already been dropped...
273    /// assert!(rx.has_changed().is_err());
274    /// // ...the modified value is still readable and detected as changed.
275    /// assert_eq!(*rx.borrow(), "goodbye");
276    /// assert!(rx.borrow().has_changed());
277    ///
278    /// // Read the changed value and mark it as seen.
279    /// {
280    ///     let received = rx.borrow_and_update();
281    ///     assert_eq!(*received, "goodbye");
282    ///     assert!(received.has_changed());
283    ///     // Release the read lock when leaving this scope.
284    /// }
285    ///
286    /// // Now the value has already been marked as seen and could
287    /// // never be modified again (after the sender has been dropped).
288    /// assert!(!rx.borrow().has_changed());
289    /// # }
290    /// ```
291    pub fn has_changed(&self) -> bool {
292        self.has_changed
293    }
294}

376    // To avoid contention on the lock inside the `Notify`, we store multiple
377    // copies of it. Then, we use either circular access or randomness to spread
378    // out threads over different `Notify` objects.
379    //
380    // Some simple benchmarks show that randomness performs slightly better than
381    // circular access (probably due to contention on `next`), so we prefer to
382    // use randomness when Tokio is compiled with a random number generator.
383    //
384    // When the random number generator is not available, we fall back to
385    // circular access.
386
387    pub(super) struct BigNotify {
388        #[cfg(not(all(not(loom), feature = "sync", any(feature = "rt", feature = "macros"))))]
389        next: std::sync::atomic::AtomicUsize,
390        inner: [Notify; 8],
391    }
392
393    impl BigNotify {
394        pub(super) fn new() -> Self {
395            Self {
396                #[cfg(not(all(
397                    not(loom),
398                    feature = "sync",
399                    any(feature = "rt", feature = "macros")
400                )))]
401                next: std::sync::atomic::AtomicUsize::new(0),
402                inner: Default::default(),
403            }
404        }
405
406        pub(super) fn notify_waiters(&self) {
407            for notify in &self.inner {
408                notify.notify_waiters();
409            }
410        }
411
412        /// This function implements the case where randomness is not available.
413        #[cfg(not(all(not(loom), feature = "sync", any(feature = "rt", feature = "macros"))))]
414        pub(super) fn notified(&self) -> Notified<'_> {
415            let i = self.next.fetch_add(1, std::sync::atomic::Ordering::Relaxed) % 8;
416            self.inner[i].notified()
417        }
418
419        /// This function implements the case where randomness is available.
420        #[cfg(all(not(loom), feature = "sync", any(feature = "rt", feature = "macros")))]
421        pub(super) fn notified(&self) -> Notified<'_> {
422            let i = crate::runtime::context::thread_rng_n(8) as usize;
423            self.inner[i].notified()
424        }
425    }

518/// Creates a new watch channel, returning the "send" and "receive" handles.
519///
520/// All values sent by [`Sender`] will become visible to the [`Receiver`] handles.
521/// Only the last value sent is made available to the [`Receiver`] half. All
522/// intermediate values are dropped.
523///
524/// # Examples
525///
526/// The following example prints `hello! world! `.
527///
528/// ```
529/// use tokio::sync::watch;
530/// use tokio::time::{Duration, sleep};
531///
532/// # async fn dox() -> Result<(), Box<dyn std::error::Error>> {
533/// let (tx, mut rx) = watch::channel("hello");
534///
535/// tokio::spawn(async move {
536///     // Use the equivalent of a "do-while" loop so the initial value is
537///     // processed before awaiting the `changed()` future.
538///     loop {
539///         println!("{}! ", *rx.borrow_and_update());
540///         if rx.changed().await.is_err() {
541///             break;
542///         }
543///     }
544/// });
545///
546/// sleep(Duration::from_millis(100)).await;
547/// tx.send("world")?;
548/// # Ok(())
549/// # }
550/// ```
551///
552/// [`Sender`]: struct@Sender
553/// [`Receiver`]: struct@Receiver
554pub fn channel<T>(init: T) -> (Sender<T>, Receiver<T>) {
555    let shared = Arc::new(Shared {
556        value: RwLock::new(init),
557        state: AtomicState::new(),
558        ref_count_rx: AtomicUsize::new(1),
559        ref_count_tx: AtomicUsize::new(1),
560        notify_rx: big_notify::BigNotify::new(),
561        notify_tx: Notify::new(),
562    });
563
564    let tx = Sender {
565        shared: shared.clone(),
566    };
567
568    let rx = Receiver {
569        shared,
570        version: Version::INITIAL,
571    };
572
573    (tx, rx)
574}

576impl<T> Receiver<T> {
577    fn from_shared(version: Version, shared: Arc<Shared<T>>) -> Self {
578        // No synchronization necessary as this is only used as a counter and
579        // not memory access.
580        shared.ref_count_rx.fetch_add(1, Relaxed);
581
582        Self { shared, version }
583    }

585    /// Returns a reference to the most recently sent value.
586    ///
587    /// This method does not mark the returned value as seen, so future calls to
588    /// [`changed`] may return immediately even if you have already seen the
589    /// value with a call to `borrow`.
590    ///
591    /// Outstanding borrows hold a read lock on the inner value. This means that
592    /// long-lived borrows could cause the producer half to block. It is recommended
593    /// to keep the borrow as short-lived as possible. Additionally, if you are
594    /// running in an environment that allows `!Send` futures, you must ensure that
595    /// the returned `Ref` type is never held alive across an `.await` point,
596    /// otherwise, it can lead to a deadlock.
597    ///
598    /// The priority policy of the lock is dependent on the underlying lock
599    /// implementation, and this type does not guarantee that any particular policy
600    /// will be used. In particular, a producer which is waiting to acquire the lock
601    /// in `send` might or might not block concurrent calls to `borrow`, e.g.:
602    ///
603    /// <details><summary>Potential deadlock example</summary>
604    ///
605    /// ```text
606    /// // Task 1 (on thread A)    |  // Task 2 (on thread B)
607    /// let _ref1 = rx.borrow();   |
608    ///                            |  // will block
609    ///                            |  let _ = tx.send(());
610    /// // may deadlock            |
611    /// let _ref2 = rx.borrow();   |
612    /// ```
613    /// </details>
614    ///
615    /// For more information on when to use this method versus
616    /// [`borrow_and_update`], see [here](self#borrow_and_update-versus-borrow).
617    ///
618    /// [`changed`]: Receiver::changed
619    /// [`borrow_and_update`]: Receiver::borrow_and_update
620    ///
621    /// # Examples
622    ///
623    /// ```
624    /// use tokio::sync::watch;
625    ///
626    /// let (_, rx) = watch::channel("hello");
627    /// assert_eq!(*rx.borrow(), "hello");
628    /// ```
629    pub fn borrow(&self) -> Ref<'_, T> {
630        let inner = self.shared.value.read();
631
632        // After obtaining a read-lock no concurrent writes could occur
633        // and the loaded version matches that of the borrowed reference.
634        let new_version = self.shared.state.load().version();
635        let has_changed = self.version != new_version;
636
637        Ref { inner, has_changed }
638    }
639
640    /// Returns a reference to the most recently sent value and marks that value
641    /// as seen.
642    ///
643    /// This method marks the current value as seen. Subsequent calls to [`changed`]
644    /// will not return immediately until the [`Sender`] has modified the shared
645    /// value again.
646    ///
647    /// Outstanding borrows hold a read lock on the inner value. This means that
648    /// long-lived borrows could cause the producer half to block. It is recommended
649    /// to keep the borrow as short-lived as possible. Additionally, if you are
650    /// running in an environment that allows `!Send` futures, you must ensure that
651    /// the returned `Ref` type is never held alive across an `.await` point,
652    /// otherwise, it can lead to a deadlock.
653    ///
654    /// The priority policy of the lock is dependent on the underlying lock
655    /// implementation, and this type does not guarantee that any particular policy
656    /// will be used. In particular, a producer which is waiting to acquire the lock
657    /// in `send` might or might not block concurrent calls to `borrow`, e.g.:
658    ///
659    /// <details><summary>Potential deadlock example</summary>
660    ///
661    /// ```text
662    /// // Task 1 (on thread A)                |  // Task 2 (on thread B)
663    /// let _ref1 = rx1.borrow_and_update();   |
664    ///                                        |  // will block
665    ///                                        |  let _ = tx.send(());
666    /// // may deadlock                        |
667    /// let _ref2 = rx2.borrow_and_update();   |
668    /// ```
669    /// </details>
670    ///
671    /// For more information on when to use this method versus [`borrow`], see
672    /// [here](self#borrow_and_update-versus-borrow).
673    ///
674    /// [`changed`]: Receiver::changed
675    /// [`borrow`]: Receiver::borrow
676    pub fn borrow_and_update(&mut self) -> Ref<'_, T> {
677        let inner = self.shared.value.read();
678
679        // After obtaining a read-lock no concurrent writes could occur
680        // and the loaded version matches that of the borrowed reference.
681        let new_version = self.shared.state.load().version();
682        let has_changed = self.version != new_version;
683
684        // Mark the shared value as seen by updating the version
685        self.version = new_version;
686
687        Ref { inner, has_changed }
688    }
689
690    /// Checks if this channel contains a message that this receiver has not yet
691    /// seen. The current value will not be marked as seen.
692    ///
693    /// Although this method is called `has_changed`, it does not check
694    /// messages for equality, so this call will return true even if the current
695    /// message is equal to the previous message.
696    ///
697    /// # Errors
698    ///
699    /// Returns a [`RecvError`](error::RecvError) if and only if the channel has been closed.
700    ///
701    /// # Examples
702    ///
703    /// ## Basic usage
704    ///
705    /// ```
706    /// use tokio::sync::watch;
707    ///
708    /// # #[tokio::main(flavor = "current_thread")]
709    /// # async fn main() {
710    /// let (tx, mut rx) = watch::channel("hello");
711    ///
712    /// tx.send("goodbye").unwrap();
713    ///
714    /// assert!(rx.has_changed().unwrap());
715    /// assert_eq!(*rx.borrow_and_update(), "goodbye");
716    ///
717    /// // The value has been marked as seen
718    /// assert!(!rx.has_changed().unwrap());
719    /// # }
720    /// ```
721    ///
722    /// ## Closed channel example
723    ///
724    /// ```
725    /// use tokio::sync::watch;
726    ///
727    /// # #[tokio::main(flavor = "current_thread")]
728    /// # async fn main() {
729    /// let (tx, rx) = watch::channel("hello");
730    /// tx.send("goodbye").unwrap();
731    ///
732    /// drop(tx);
733    ///
734    /// // The channel is closed
735    /// assert!(rx.has_changed().is_err());
736    /// # }
737    /// ```
738    pub fn has_changed(&self) -> Result<bool, error::RecvError> {
739        // Load the version from the state
740        let state = self.shared.state.load();
741        if state.is_closed() {
742            // All senders have dropped.
743            return Err(error::RecvError(()));
744        }
745        let new_version = state.version();
746
747        Ok(self.version != new_version)
748    }

750    /// Checks if the channel has been closed. This happens when all [`Sender`]s
751    /// have been dropped.
752    ///
753    /// # Examples
754    ///
755    /// ```
756    /// use tokio::sync::watch;
757    ///
758    /// let (tx, rx) = watch::channel(());
759    /// assert!(!rx.is_closed());
760    ///
761    /// drop(tx);
762    /// assert!(rx.is_closed());
763    /// ```
764    pub fn is_closed(&self) -> bool {
765        self.shared.state.load().is_closed()
766    }

768    /// Marks the state as changed.
769    ///
770    /// After invoking this method [`has_changed()`](Self::has_changed)
771    /// returns `true` and [`changed()`](Self::changed) returns
772    /// immediately, regardless of whether a new value has been sent.
773    ///
774    /// This is useful for triggering an initial change notification after
775    /// subscribing to synchronize new receivers.
776    pub fn mark_changed(&mut self) {
777        self.version.decrement();
778    }

780    /// Marks the state as unchanged.
781    ///
782    /// The current value will be considered seen by the receiver.
783    ///
784    /// This is useful if you are not interested in the current value
785    /// visible in the receiver.
786    pub fn mark_unchanged(&mut self) {
787        let current_version = self.shared.state.load().version();
788        self.version = current_version;
789    }

791    /// Waits for a change notification, then marks the current value as seen.
792    ///
793    /// If the current value in the channel has not yet been marked seen when
794    /// this method is called, the method marks that value seen and returns
795    /// immediately. If the newest value has already been marked seen, then the
796    /// method sleeps until a new message is sent by a [`Sender`] connected to
797    /// this `Receiver`, or until all [`Sender`]s are dropped.
798    ///
799    /// For more information, see
800    /// [*Change notifications*](self#change-notifications) in the module-level documentation.
801    ///
802    /// # Errors
803    ///
804    /// Returns a [`RecvError`](error::RecvError) if the channel has been closed __AND__
805    /// the current value is seen.
806    ///
807    /// # Cancel safety
808    ///
809    /// This method is cancel safe. If you use it as a branch in
810    /// [`tokio::select!`](crate::select) and another branch
811    /// completes first, then it is guaranteed that no values have been marked
812    /// seen by this call to `changed`.
813    ///
814    /// [`Sender`]: struct@Sender
815    ///
816    /// # Examples
817    ///
818    /// ```
819    /// use tokio::sync::watch;
820    ///
821    /// # #[tokio::main(flavor = "current_thread")]
822    /// # async fn main() {
823    /// let (tx, mut rx) = watch::channel("hello");
824    ///
825    /// tokio::spawn(async move {
826    ///     tx.send("goodbye").unwrap();
827    /// });
828    ///
829    /// assert!(rx.changed().await.is_ok());
830    /// assert_eq!(*rx.borrow_and_update(), "goodbye");
831    ///
832    /// // The `tx` handle has been dropped
833    /// assert!(rx.changed().await.is_err());
834    /// # }
835    /// ```
836    pub async fn changed(&mut self) -> Result<(), error::RecvError> {
837        cooperative(changed_impl(&self.shared, &mut self.version)).await
838    }

840    /// Waits for a value that satisfies the provided condition.
841    ///
842    /// This method will call the provided closure whenever something is sent on
843    /// the channel. Once the closure returns `true`, this method will return a
844    /// reference to the value that was passed to the closure.
845    ///
846    /// Before `wait_for` starts waiting for changes, it will call the closure
847    /// on the current value. If the closure returns `true` when given the
848    /// current value, then `wait_for` will immediately return a reference to
849    /// the current value. This is the case even if the current value is already
850    /// considered seen.
851    ///
852    /// The watch channel only keeps track of the most recent value, so if
853    /// several messages are sent faster than `wait_for` is able to call the
854    /// closure, then it may skip some updates. Whenever the closure is called,
855    /// it will be called with the most recent value.
856    ///
857    /// When this function returns, the value that was passed to the closure
858    /// when it returned `true` will be considered seen.
859    ///
860    /// If the channel is closed, then `wait_for` will return a [`RecvError`].
861    /// Once this happens, no more messages can ever be sent on the channel.
862    /// When an error is returned, it is guaranteed that the closure has been
863    /// called on the last value, and that it returned `false` for that value.
864    /// (If the closure returned `true`, then the last value would have been
865    /// returned instead of the error.)
866    ///
867    /// Like the [`borrow`] method, the returned borrow holds a read lock on the
868    /// inner value. This means that long-lived borrows could cause the producer
869    /// half to block. It is recommended to keep the borrow as short-lived as
870    /// possible. See the documentation of `borrow` for more information on
871    /// this.
872    ///
873    /// [`borrow`]: Receiver::borrow
874    /// [`RecvError`]: error::RecvError
875    ///
876    /// # Cancel safety
877    ///
878    /// This method is cancel safe. If you use it as a branch in
879    /// [`tokio::select!`](crate::select) and another branch
880    /// completes first, then it is guaranteed that the last seen value `val`
881    /// (if any) satisfies `f(val) == false`.
882    ///
883    /// # Panics
884    ///
885    /// If and only if the closure `f` panics. In that case, no resource owned
886    /// or shared by this [`Receiver`] will be poisoned.
887    ///
888    /// # Examples
889    ///
890    /// ```
891    /// use tokio::sync::watch;
892    /// use tokio::time::{sleep, Duration};
893    ///
894    /// #[tokio::main(flavor = "current_thread", start_paused = true)]
895    /// async fn main() {
896    ///     let (tx, mut rx) = watch::channel("hello");
897    ///
898    ///     tokio::spawn(async move {
899    ///         sleep(Duration::from_secs(1)).await;
900    ///         tx.send("goodbye").unwrap();
901    ///     });
902    ///
903    ///     assert!(rx.wait_for(|val| *val == "goodbye").await.is_ok());
904    ///     assert_eq!(*rx.borrow(), "goodbye");
905    /// }
906    /// ```
907    pub async fn wait_for(
908        &mut self,
909        f: impl FnMut(&T) -> bool,
910    ) -> Result<Ref<'_, T>, error::RecvError> {
911        cooperative(self.wait_for_inner(f)).await
912    }
913
914    async fn wait_for_inner(
915        &mut self,
916        mut f: impl FnMut(&T) -> bool,
917    ) -> Result<Ref<'_, T>, error::RecvError> {
918        let mut closed = false;
919        loop {
920            {
921                let inner = self.shared.value.read();
922
923                let new_version = self.shared.state.load().version();
924                let has_changed = self.version != new_version;
925                self.version = new_version;
926
927                if !closed || has_changed {
928                    let result = panic::catch_unwind(panic::AssertUnwindSafe(|| f(&inner)));
929                    match result {
930                        Ok(true) => {
931                            return Ok(Ref { inner, has_changed });
932                        }
933                        Ok(false) => {
934                            // Skip the value.
935                        }
936                        Err(panicked) => {
937                            // Drop the read-lock to avoid poisoning it.
938                            drop(inner);
939                            // Forward the panic to the caller.
940                            panic::resume_unwind(panicked);
941                            // Unreachable
942                        }
943                    };
944                }
945            }
946
947            if closed {
948                return Err(error::RecvError(()));
949            }
950
951            // Wait for the value to change.
952            closed = changed_impl(&self.shared, &mut self.version).await.is_err();
953        }
954    }

957    ///
958    /// # Examples
959    ///
960    /// ```
961    /// let (tx, rx) = tokio::sync::watch::channel(true);
962    /// let rx2 = rx.clone();
963    /// assert!(rx.same_channel(&rx2));
964    ///
965    /// let (tx3, rx3) = tokio::sync::watch::channel(true);
966    /// assert!(!rx3.same_channel(&rx2));

969        Arc::ptr_eq(&self.shared, &other.shared)
970    }

979fn maybe_changed<T>(
980    shared: &Shared<T>,
981    version: &mut Version,
982) -> Option<Result<(), error::RecvError>> {
983    // Load the version from the state
984    let state = shared.state.load();
985    let new_version = state.version();
986
987    if *version != new_version {
988        // Observe the new version and return
989        *version = new_version;
990        return Some(Ok(()));
991    }
992
993    if state.is_closed() {
994        // All senders have been dropped.
995        return Some(Err(error::RecvError(())));
996    }
997
998    None
999}
1000
1001async fn changed_impl<T>(
1002    shared: &Shared<T>,
1003    version: &mut Version,
1004) -> Result<(), error::RecvError> {
1005    crate::trace::async_trace_leaf().await;
1006
1007    loop {
1008        // In order to avoid a race condition, we first request a notification,
1009        // **then** check the current value's version. If a new version exists,
1010        // the notification request is dropped.
1011        let notified = shared.notify_rx.notified();
1012
1013        if let Some(ret) = maybe_changed(shared, version) {
1014            return ret;
1015        }
1016
1017        notified.await;
1018        // loop around again in case the wake-up was spurious
1019    }
1020}

1031impl<T> Drop for Receiver<T> {
1032    fn drop(&mut self) {
1033        // No synchronization necessary as this is only used as a counter and
1034        // not memory access.
1035        if 1 == self.shared.ref_count_rx.fetch_sub(1, Relaxed) {
1036            // This is the last `Receiver` handle, tasks waiting on `Sender::closed()`
1037            self.shared.notify_tx.notify_waiters();
1038        }
1039    }
1040}

1042impl<T> Sender<T> {
1043    /// Creates the sending-half of the [`watch`] channel.
1044    ///
1045    /// See documentation of [`watch::channel`] for errors when calling this function.
1046    /// Beware that attempting to send a value when there are no receivers will
1047    /// return an error.
1048    ///
1049    /// [`watch`]: crate::sync::watch
1050    /// [`watch::channel`]: crate::sync::watch
1051    ///
1052    /// # Examples
1053    /// ```
1054    /// let sender = tokio::sync::watch::Sender::new(0u8);
1055    /// assert!(sender.send(3).is_err());
1056    /// let _rec = sender.subscribe();
1057    /// assert!(sender.send(4).is_ok());
1058    /// ```
1059    pub fn new(init: T) -> Self {
1060        let (tx, _) = channel(init);
1061        tx
1062    }
1063
1064    /// Sends a new value via the channel, notifying all receivers.
1065    ///
1066    /// This method fails if the channel is closed, which is the case when
1067    /// every receiver has been dropped. It is possible to reopen the channel
1068    /// using the [`subscribe`] method. However, when `send` fails, the value
1069    /// isn't made available for future receivers (but returned with the
1070    /// [`SendError`]).
1071    ///
1072    /// To always make a new value available for future receivers, even if no
1073    /// receiver currently exists, one of the other send methods
1074    /// ([`send_if_modified`], [`send_modify`], or [`send_replace`]) can be
1075    /// used instead.
1076    ///
1077    /// [`subscribe`]: Sender::subscribe
1078    /// [`SendError`]: error::SendError
1079    /// [`send_if_modified`]: Sender::send_if_modified
1080    /// [`send_modify`]: Sender::send_modify
1081    /// [`send_replace`]: Sender::send_replace
1082    pub fn send(&self, value: T) -> Result<(), error::SendError<T>> {
1083        // This is pretty much only useful as a hint anyway, so synchronization isn't critical.
1084        if 0 == self.receiver_count() {
1085            return Err(error::SendError(value));
1086        }
1087
1088        self.send_replace(value);
1089        Ok(())
1090    }
1091
1092    /// Modifies the watched value **unconditionally** in-place,
1093    /// notifying all receivers.
1094    ///
1095    /// This can be useful for modifying the watched value, without
1096    /// having to allocate a new instance. Additionally, this
1097    /// method permits sending values even when there are no receivers.
1098    ///
1099    /// Prefer to use the more versatile function [`Self::send_if_modified()`]
1100    /// if the value is only modified conditionally during the mutable borrow
1101    /// to prevent unneeded change notifications for unmodified values.
1102    ///
1103    /// # Panics
1104    ///
1105    /// This function panics when the invocation of the `modify` closure panics.
1106    /// No receivers are notified when panicking. All changes of the watched
1107    /// value applied by the closure before panicking will be visible in
1108    /// subsequent calls to `borrow`.
1109    ///
1110    /// # Examples
1111    ///
1112    /// ```
1113    /// use tokio::sync::watch;
1114    ///
1115    /// struct State {
1116    ///     counter: usize,
1117    /// }
1118    /// let (state_tx, state_rx) = watch::channel(State { counter: 0 });
1119    /// state_tx.send_modify(|state| state.counter += 1);
1120    /// assert_eq!(state_rx.borrow().counter, 1);
1121    /// ```
1122    pub fn send_modify<F>(&self, modify: F)
1123    where
1124        F: FnOnce(&mut T),
1125    {
1126        self.send_if_modified(|value| {
1127            modify(value);
1128            true
1129        });
1130    }
1131
1132    /// Modifies the watched value **conditionally** in-place,
1133    /// notifying all receivers only if modified.
1134    ///
1135    /// This can be useful for modifying the watched value, without
1136    /// having to allocate a new instance. Additionally, this
1137    /// method permits sending values even when there are no receivers.
1138    ///
1139    /// The `modify` closure must return `true` if the value has actually
1140    /// been modified during the mutable borrow. It should only return `false`
1141    /// if the value is guaranteed to be unmodified despite the mutable
1142    /// borrow.
1143    ///
1144    /// Receivers are only notified if the closure returned `true`. If the
1145    /// closure has modified the value but returned `false` this results
1146    /// in a *silent modification*, i.e. the modified value will be visible
1147    /// in subsequent calls to `borrow`, but receivers will not receive
1148    /// a change notification.
1149    ///
1150    /// Returns the result of the closure, i.e. `true` if the value has
1151    /// been modified and `false` otherwise.
1152    ///
1153    /// # Panics
1154    ///
1155    /// This function panics when the invocation of the `modify` closure panics.
1156    /// No receivers are notified when panicking. All changes of the watched
1157    /// value applied by the closure before panicking will be visible in
1158    /// subsequent calls to `borrow`.
1159    ///
1160    /// # Examples
1161    ///
1162    /// ```
1163    /// use tokio::sync::watch;
1164    ///
1165    /// struct State {
1166    ///     counter: usize,
1167    /// }
1168    /// let (state_tx, mut state_rx) = watch::channel(State { counter: 1 });
1169    /// let inc_counter_if_odd = |state: &mut State| {
1170    ///     if state.counter % 2 == 1 {
1171    ///         state.counter += 1;
1172    ///         return true;
1173    ///     }
1174    ///     false
1175    /// };
1176    ///
1177    /// assert_eq!(state_rx.borrow().counter, 1);
1178    ///
1179    /// assert!(!state_rx.has_changed().unwrap());
1180    /// assert!(state_tx.send_if_modified(inc_counter_if_odd));
1181    /// assert!(state_rx.has_changed().unwrap());
1182    /// assert_eq!(state_rx.borrow_and_update().counter, 2);
1183    ///
1184    /// assert!(!state_rx.has_changed().unwrap());
1185    /// assert!(!state_tx.send_if_modified(inc_counter_if_odd));
1186    /// assert!(!state_rx.has_changed().unwrap());
1187    /// assert_eq!(state_rx.borrow_and_update().counter, 2);
1188    /// ```
1189    pub fn send_if_modified<F>(&self, modify: F) -> bool
1190    where
1191        F: FnOnce(&mut T) -> bool,
1192    {
1193        {
1194            // Acquire the write lock and update the value.
1195            let mut lock = self.shared.value.write();
1196
1197            // Update the value and catch possible panic inside func.
1198            let result = panic::catch_unwind(panic::AssertUnwindSafe(|| modify(&mut lock)));
1199            match result {
1200                Ok(modified) => {
1201                    if !modified {
1202                        // Abort, i.e. don't notify receivers if unmodified
1203                        return false;
1204                    }
1205                    // Continue if modified
1206                }
1207                Err(panicked) => {
1208                    // Drop the lock to avoid poisoning it.
1209                    drop(lock);
1210                    // Forward the panic to the caller.
1211                    panic::resume_unwind(panicked);
1212                    // Unreachable
1213                }
1214            };
1215
1216            self.shared.state.increment_version_while_locked();
1217
1218            // Release the write lock.
1219            //
1220            // Incrementing the version counter while holding the lock ensures
1221            // that receivers are able to figure out the version number of the
1222            // value they are currently looking at.
1223            drop(lock);
1224        }
1225
1226        self.shared.notify_rx.notify_waiters();
1227
1228        true
1229    }

1231    /// Sends a new value via the channel, notifying all receivers and returning
1232    /// the previous value in the channel.
1233    ///
1234    /// This can be useful for reusing the buffers inside a watched value.
1235    /// Additionally, this method permits sending values even when there are no
1236    /// receivers.
1237    ///
1238    /// # Examples
1239    ///
1240    /// ```
1241    /// use tokio::sync::watch;
1242    ///
1243    /// let (tx, _rx) = watch::channel(1);
1244    /// assert_eq!(tx.send_replace(2), 1);
1245    /// assert_eq!(tx.send_replace(3), 2);
1246    /// ```
1247    pub fn send_replace(&self, mut value: T) -> T {
1248        // swap old watched value with the new one
1249        self.send_modify(|old| mem::swap(old, &mut value));
1250
1251        value
1252    }

1254    /// Returns a reference to the most recently sent value
1255    ///
1256    /// Outstanding borrows hold a read lock on the inner value. This means that
1257    /// long-lived borrows could cause the producer half to block. It is recommended
1258    /// to keep the borrow as short-lived as possible. Additionally, if you are
1259    /// running in an environment that allows `!Send` futures, you must ensure that
1260    /// the returned `Ref` type is never held alive across an `.await` point,
1261    /// otherwise, it can lead to a deadlock.
1262    ///
1263    /// # Examples
1264    ///
1265    /// ```
1266    /// use tokio::sync::watch;
1267    ///
1268    /// let (tx, _) = watch::channel("hello");
1269    /// assert_eq!(*tx.borrow(), "hello");
1270    /// ```
1271    pub fn borrow(&self) -> Ref<'_, T> {
1272        let inner = self.shared.value.read();
1273
1274        // The sender/producer always sees the current version
1275        let has_changed = false;
1276
1277        Ref { inner, has_changed }
1278    }

1280    /// Checks if the channel has been closed. This happens when all receivers
1281    /// have dropped.
1282    ///
1283    /// # Examples
1284    ///
1285    /// ```
1286    /// let (tx, rx) = tokio::sync::watch::channel(());
1287    /// assert!(!tx.is_closed());
1288    ///
1289    /// drop(rx);
1290    /// assert!(tx.is_closed());
1291    /// ```
1292    pub fn is_closed(&self) -> bool {
1293        self.receiver_count() == 0
1294    }
1295
1296    /// Completes when all receivers have dropped.
1297    ///
1298    /// This allows the producer to get notified when interest in the produced
1299    /// values is canceled and immediately stop doing work. Once a channel is
1300    /// closed, the only way to reopen it is to call [`Sender::subscribe`] to
1301    /// get a new receiver.
1302    ///
1303    /// If the channel becomes closed for a brief amount of time (e.g., the last
1304    /// receiver is dropped and then `subscribe` is called), then this call to
1305    /// `closed` might return, but it is also possible that it does not "notice"
1306    /// that the channel was closed for a brief amount of time.
1307    ///
1308    /// # Cancel safety
1309    ///
1310    /// This method is cancel safe.
1311    ///
1312    /// # Examples
1313    ///
1314    /// ```
1315    /// use tokio::sync::watch;
1316    ///
1317    /// # #[tokio::main(flavor = "current_thread")]
1318    /// # async fn main() {
1319    /// let (tx, rx) = watch::channel("hello");
1320    ///
1321    /// tokio::spawn(async move {
1322    ///     // use `rx`
1323    ///     drop(rx);
1324    /// });
1325    ///
1326    /// // Waits for `rx` to drop
1327    /// tx.closed().await;
1328    /// println!("the `rx` handles dropped")
1329    /// # }
1330    /// ```
1331    pub async fn closed(&self) {
1332        cooperative(async {
1333            crate::trace::async_trace_leaf().await;
1334
1335            while self.receiver_count() > 0 {
1336                let notified = self.shared.notify_tx.notified();
1337
1338                if self.receiver_count() == 0 {
1339                    return;
1340                }
1341
1342                notified.await;
1343                // The channel could have been reopened in the meantime by calling
1344                // `subscribe`, so we loop again.
1345            }
1346        })
1347        .await;
1348    }

1350    /// Creates a new [`Receiver`] connected to this `Sender`.
1351    ///
1352    /// All messages sent before this call to `subscribe` are initially marked
1353    /// as seen by the new `Receiver`.
1354    ///
1355    /// This method can be called even if there are no other receivers. In this
1356    /// case, the channel is reopened.
1357    ///
1358    /// # Examples
1359    ///
1360    /// The new channel will receive messages sent on this `Sender`.
1361    ///
1362    /// ```
1363    /// use tokio::sync::watch;
1364    ///
1365    /// # #[tokio::main(flavor = "current_thread")]
1366    /// # async fn main() {
1367    /// let (tx, _rx) = watch::channel(0u64);
1368    ///
1369    /// tx.send(5).unwrap();
1370    ///
1371    /// let rx = tx.subscribe();
1372    /// assert_eq!(5, *rx.borrow());
1373    ///
1374    /// tx.send(10).unwrap();
1375    /// assert_eq!(10, *rx.borrow());
1376    /// # }
1377    /// ```
1378    ///
1379    /// The most recent message is considered seen by the channel, so this test
1380    /// is guaranteed to pass.
1381    ///
1382    /// ```
1383    /// use tokio::sync::watch;
1384    /// use tokio::time::Duration;
1385    ///
1386    /// # #[tokio::main(flavor = "current_thread")]
1387    /// # async fn main() {
1388    /// let (tx, _rx) = watch::channel(0u64);
1389    /// tx.send(5).unwrap();
1390    /// let mut rx = tx.subscribe();
1391    ///
1392    /// tokio::spawn(async move {
1393    ///     // by spawning and sleeping, the message is sent after `main`
1394    ///     // hits the call to `changed`.
1395    ///     # if false {
1396    ///     tokio::time::sleep(Duration::from_millis(10)).await;
1397    ///     # }
1398    ///     tx.send(100).unwrap();
1399    /// });
1400    ///
1401    /// rx.changed().await.unwrap();
1402    /// assert_eq!(100, *rx.borrow());
1403    /// # }
1404    /// ```
1405    pub fn subscribe(&self) -> Receiver<T> {
1406        let shared = self.shared.clone();
1407        let version = shared.state.load().version();
1408
1409        // The CLOSED bit in the state tracks only whether the sender is
1410        // dropped, so we do not need to unset it if this reopens the channel.
1411        Receiver::from_shared(version, shared)
1412    }

1480            self.shared.notify_rx.notify_waiters();
1481        }
