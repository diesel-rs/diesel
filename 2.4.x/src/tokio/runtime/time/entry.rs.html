1//! Timer state structures.
2//!
3//! This module contains the heart of the intrusive timer implementation, and as
4//! such the structures inside are full of tricky concurrency and unsafe code.
5//!
6//! # Ground rules
7//!
8//! The heart of the timer implementation here is the [`TimerShared`] structure,
9//! shared between the [`TimerEntry`] and the driver. Generally, we permit access
10//! to [`TimerShared`] ONLY via either 1) a mutable reference to [`TimerEntry`] or
11//! 2) a held driver lock.
12//!
13//! It follows from this that any changes made while holding BOTH 1 and 2 will
14//! be reliably visible, regardless of ordering. This is because of the `acq/rel`
15//! fences on the driver lock ensuring ordering with 2, and rust mutable
16//! reference rules for 1 (a mutable reference to an object can't be passed
17//! between threads without an `acq/rel` barrier, and same-thread we have local
18//! happens-before ordering).
19//!
20//! # State field
21//!
22//! Each timer has a state field associated with it. This field contains either
23//! the current scheduled time, or a special flag value indicating its state.
24//! This state can either indicate that the timer is on the 'pending' queue (and
25//! thus will be fired with an `Ok(())` result soon) or that it has already been
26//! fired/deregistered.
27//!
28//! This single state field allows for code that is firing the timer to
29//! synchronize with any racing `reset` calls reliably.
30//!
31//! # Registered vs true timeouts
32//!
33//! To allow for the use case of a timeout that is periodically reset before
34//! expiration to be as lightweight as possible, we support optimistically
35//! lock-free timer resets, in the case where a timer is rescheduled to a later
36//! point than it was originally scheduled for.
37//!
38//! This is accomplished by lazily rescheduling timers. That is, we update the
39//! state field with the true expiration of the timer from the holder of
40//! the [`TimerEntry`]. When the driver services timers (ie, whenever it's
41//! walking lists of timers), it checks this "true when" value, and reschedules
42//! based on it.
43//!
44//! We do, however, also need to track what the expiration time was when we
45//! originally registered the timer; this is used to locate the right linked
46//! list when the timer is being cancelled.
47//! This is referred to as the `registered_when` internally.
48//!
49//! There is of course a race condition between timer reset and timer
50//! expiration. If the driver fails to observe the updated expiration time, it
51//! could trigger expiration of the timer too early. However, because
52//! [`mark_pending`][mark_pending] performs a compare-and-swap, it will identify this race and
53//! refuse to mark the timer as pending.
54//!
55//! [mark_pending]: TimerHandle::mark_pending

79/// This structure holds the current shared state of the timer - its scheduled
80/// time (if registered), or otherwise the result of the timer completing, as
81/// well as the registered waker.
82///
83/// Generally, the `StateCell` is only permitted to be accessed from two contexts:
84/// Either a thread holding the corresponding `&mut TimerEntry`, or a thread
85/// holding the timer driver lock. The write actions on the `StateCell` amount to
86/// passing "ownership" of the `StateCell` between these contexts; moving a timer
87/// from the `TimerEntry` to the driver requires _both_ holding the `&mut
88/// TimerEntry` and the driver lock, while moving it back (firing the timer)
89/// requires only the driver lock.
90pub(super) struct StateCell {
91    /// Holds either the scheduled expiration time for this timer, or (if the
92    /// timer has been fired and is unregistered), `u64::MAX`.
93    state: AtomicU64,
94    /// If the timer is fired (an Acquire order read on state shows
95    /// `u64::MAX`), holds the result that should be returned from
96    /// polling the timer. Otherwise, the contents are unspecified and reading
97    /// without holding the driver lock is undefined behavior.
98    result: UnsafeCell<TimerResult>,
99    /// The currently-registered waker
100    waker: AtomicWaker,
101}
102

105        Self::new()

133            None

139    /// If the timer is completed, returns the result of the timer. Otherwise,
140    /// returns None and registers the waker.
141    fn poll(&self, waker: &Waker) -> Poll<TimerResult> {

143        // observe the new waker, or we will observe a racing fire to have set
144        // the state, or both.
145        self.waker.register_by_ref(waker);

147        self.read_state()
148    }

155            // the result, and then writing (with release ordering) the state
156            // field.
157            Poll::Ready(unsafe { self.result.with(|p| *p) })
158        } else {

161    }

201    /// Fires the timer, setting the result to the provided result.
202    ///
203    /// Returns:
204    /// * `Some(waker)` - if fired and a waker needs to be invoked once the
205    ///   driver lock is released
206    /// * `None` - if fired and a waker does not need to be invoked, or if
207    ///   already fired
208    ///
209    /// SAFETY: The driver lock must be held.
210    unsafe fn fire(&self, result: TimerResult) -> Option<Waker> {
211        // Quick initial check to see if the timer is already fired. Since
212        // firing the timer can only happen with the driver lock held, we know
213        // we shouldn't be able to "miss" a transition to a fired state, even
214        // with relaxed ordering.
215        let cur_state = self.state.load(Ordering::Relaxed);
216        if cur_state == STATE_DEREGISTERED {
217            return None;
218        }
219
220        // SAFETY: We assume the driver lock is held and the timer is not
221        // fired, so only the driver is accessing this field.
222        //
223        // We perform a release-ordered store to state below, to ensure this
224        // write is visible before the state update is visible.
225        unsafe { self.result.with_mut(|p| *p = result) };
226
227        self.state.store(STATE_DEREGISTERED, Ordering::Release);
228
229        self.waker.take_waker()
230    }

233    /// expiration time.

241        // fence when we release the lock.
242        self.state.store(timestamp, Ordering::Relaxed);
243    }
244
245    /// Attempts to adjust the timer to a new timestamp.
246    ///
247    /// If the timer has already been fired, is pending firing, or the new
248    /// timestamp is earlier than the old timestamp, (or occasionally
249    /// spuriously) returns Err without changing the timer's state. In this
250    /// case, the timer must be deregistered and re-registered.
251    fn extend_expiration(&self, new_timestamp: u64) -> Result<(), ()> {
252        let mut prior = self.state.load(Ordering::Relaxed);
253        loop {
254            if new_timestamp < prior || prior >= STATE_MIN_VALUE {
255                return Err(());
256            }
257
258            match self.state.compare_exchange_weak(
259                prior,
260                new_timestamp,
261                Ordering::AcqRel,
262                Ordering::Acquire,
263            ) {
264                Ok(_) => return Ok(()),
265                Err(true_prior) => prior = true_prior,
266            }
267        }
268    }
269
270    /// Returns true if the state of this timer indicates that the timer might
271    /// be registered with the driver. This check is performed with relaxed
272    /// ordering, but is conservative - if it returns false, the timer is
273    /// definitely _not_ registered.
274    pub(super) fn might_be_registered(&self) -> bool {
275        self.state.load(Ordering::Relaxed) != STATE_DEREGISTERED
276    }

324/// The shared state structure of a timer. This structure is shared between the
325/// frontend (`Entry`) and driver backend.
326///
327/// Note that this structure is located inside the `TimerEntry` structure.
328pub(crate) struct TimerShared {
329    /// A link within the doubly-linked list of timers on a particular level and
330    /// slot. Valid only if state is equal to Registered.
331    ///
332    /// Only accessed under the entry lock.
333    pointers: linked_list::Pointers<TimerShared>,
334
335    /// The time when the [`TimerEntry`] was registered into the Wheel,
336    /// [`STATE_DEREGISTERED`] means it is not registered.
337    ///
338    /// Generally owned by the driver, but is accessed by the entry when not

342    /// is only accessed either when holding the driver lock or through mutable
343    /// references to [`TimerEntry`].
344    registered_when: AtomicU64,
345
346    /// Current state. This records whether the timer entry is currently under
347    /// the ownership of the driver, and if not, its current state (not
348    /// complete, fired, error, etc).

352}

482            self.driver()

484        }
485    }
486
487    pub(crate) fn is_elapsed(&self) -> bool {
488        // Is this timer still in the timer wheel?
489        !self.inner.might_be_registered()
490    }
491
492    /// Cancels and deregisters the timer. This operation is irreversible.
493    pub(crate) fn cancel(self: Pin<&mut Self>) {
494        // We need to perform an acq/rel fence with the driver thread, and the
495        // simplest way to do so is to grab the driver lock.
496        //
497        // Why is this necessary? We're about to release this timer's memory for
498        // some other non-timer use. However, we've been doing a bunch of
499        // relaxed (or even non-atomic) writes from the driver thread, and we'll
500        // be doing more from _this thread_ (as this memory is interpreted as
501        // something else).
502        //
503        // It is critical to ensure that, from the point of view of the driver,
504        // those future non-timer writes happen-after the timer is fully fired,
505        // and from the purpose of this thread, the driver's writes all
506        // happen-before we drop the timer. This in turn requires us to perform
507        // an acquire-release barrier in _both_ directions between the driver
508        // and dropping thread.
509        //
510        // The lock acquisition in clear_entry serves this purpose. All of the
511        // driver manipulations happen with the lock held, so we can just take
512        // the lock and be sure that this drop happens-after everything the
513        // driver did so far and happens-before everything the driver does in
514        // the future. While we have the lock held, we also go ahead and
515        // deregister the entry if necessary.
516        unsafe { self.driver().clear_entry(NonNull::from(&self.inner)) };
517    }
518
519    pub(crate) fn reset(self: Pin<&mut Self>, deadline: u64) {
520        if self.inner.extend_expiration(deadline).is_ok() {
521            return;
522        }
523
524        unsafe {

561    /// Forcibly sets the true and cached expiration times to the given tick.
562    ///
563    /// SAFETY: The caller must ensure that the handle remains valid, the driver
564    /// lock is held, and that the timer is not in any wheel linked lists.
565    pub(super) unsafe fn set_expiration(&self, tick: u64) {
566        unsafe {
567            self.inner.as_ref().set_expiration(tick);
568        }
569    }
570
571    /// Attempts to mark this entry as pending. If the expiration time is after
572    /// `not_after`, however, returns an Err with the current expiration time.
573    ///
574    /// If an `Err` is returned, the `registered_when` value will be updated to this
575    /// new expiration time.
576    ///
577    /// SAFETY: The caller must ensure that the handle remains valid, the driver
578    /// lock is held, and that the timer is not in any wheel linked lists.
579    /// After returning Ok, the entry must be added to the pending list.
580    pub(super) unsafe fn mark_pending(&self, not_after: u64) -> Result<(), u64> {
581        match unsafe { self.inner.as_ref().state.mark_pending(not_after) } {
582            Ok(()) => {
583                // mark this as being on the pending queue in registered_when
584                unsafe {
585                    self.inner.as_ref().set_registered_when(STATE_DEREGISTERED);
586                }
587                Ok(())
588            }
589            Err(tick) => {
590                unsafe {
591                    self.inner.as_ref().set_registered_when(tick);
592                }
593                Err(tick)
594            }
595        }
596    }

598    /// Attempts to transition to a terminal state. If the state is already a
599    /// terminal state, does nothing.
600    ///
601    /// Because the entry might be dropped after the state is moved to a
602    /// terminal state, this function consumes the handle to ensure we don't
603    /// access the entry afterwards.
604    ///
605    /// Returns the last-registered waker, if any.
606    ///
607    /// SAFETY: The driver lock must be held while invoking this function, and
608    /// the entry must not be in any wheel linked lists.
609    pub(super) unsafe fn fire(self, completed_state: TimerResult) -> Option<Waker> {
610        unsafe { self.inner.as_ref().state.fire(completed_state) }
611    }
