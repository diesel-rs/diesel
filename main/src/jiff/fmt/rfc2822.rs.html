1/*!
2Support for printing and parsing instants using the [RFC 2822] datetime format.
3
4RFC 2822 is most commonly found when dealing with email messages.
5
6Since RFC 2822 only supports specifying a complete instant in time, the parser
7and printer in this module only use [`ZonedDateTime`] and [`Timestamp`]. If you
8need inexact time, you can get it from [`ZonedDateTime`] via
9[`ZonedDateTime::datetime`].
10
11[RFC 2822]: https://datatracker.ietf.org/doc/html/rfc2822
12
13# Incomplete support
14
15The RFC 2822 support in this crate is technically incomplete. Specifically,
16it does not support parsing comments within folding whitespace. It will parse
17comments after the datetime itself (including nested comments). See [Issue
18#39][issue39] for an example. If you find a real world use case for parsing
19comments within whitespace at any point in the datetime string, please file
20an issue. That is, the main reason it isn't currently supported is because
21it didn't seem worth the implementation complexity to account for it. But if
22there are real world use cases that need it, then that would be sufficient
23justification for adding it.
24
25RFC 2822 support should otherwise be complete, including support for parsing
26obsolete offsets.
27
28[issue39]: https://github.com/BurntSushi/jiff/issues/39
29
30# Warning
31
32The RFC 2822 format only supports writing a precise instant in time
33expressed via a time zone offset. It does *not* support serializing
34the time zone itself. This means that if you format a zoned datetime
35in a time zone like `America/New_York` and then deserialize it, the
36zoned datetime you get back will be a "fixed offset" zoned datetime.
37This in turn means it will not perform daylight saving time safe
38arithmetic.
39
40Basically, you should use the RFC 2822 format if it's required (for
41example, when dealing with email). But you should not choose it as a
42general interchange format for new applications.
43*/

75/// Convert a [`ZonedDateTime`] to an [RFC 2822] datetime string.
76///
77/// This is a convenience function for using [`DateTimePrinter`]. In
78/// particular, this always creates and allocates a new `String`. For writing
79/// to an existing string, or converting a [`Timestamp`] to an RFC 2822
80/// datetime string, you'll need to use `DateTimePrinter`.
81///
82/// [RFC 2822]: https://datatracker.ietf.org/doc/html/rfc2822
83///
84/// # Warning
85///
86/// The RFC 2822 format only supports writing a precise instant in time
87/// expressed via a time zone offset. It does *not* support serializing
88/// the time zone itself. This means that if you format a zoned datetime
89/// in a time zone like `America/New_York` and then deserialize it, the
90/// zoned datetime you get back will be a "fixed offset" zoned datetime.
91/// This in turn means it will not perform daylight saving time safe
92/// arithmetic.
93///
94/// Basically, you should use the RFC 2822 format if it's required (for
95/// example, when dealing with email). But you should not choose it as a
96/// general interchange format for new applications.
97///
98/// # Errors
99///
100/// This returns an error if the year corresponding to this timestamp cannot be
101/// represented in the RFC 2822 format. For example, a negative year.
102///
103/// # Example
104///
105/// This example shows how to convert a zoned datetime to the RFC 2822 format:
106///
107/// ```
108/// use jiff::{civil::date, fmt::rfc2822};
109///
110/// let zdt = date(2024, 6, 15).at(7, 0, 0, 0).in_tz("Australia/Hobart")?;
111/// assert_eq!(rfc2822::to_string(&zdt)?, "Sat, 15 Jun 2024 07:00:00 +1000");
112///
113/// # Ok::<(), Box<dyn std::error::Error>>(())
114/// ```
115#[cfg(feature = "alloc")]
116#[inline]
117pub fn to_string(zdt: &ZonedDateTime) -> Result<alloc::string::String, Error> {
118    let mut buf = alloc::string::String::new();
119    DEFAULT_DATETIME_PRINTER.print_zoned_datetime(zdt, &mut buf)?;
120    Ok(buf)
121}

123/// Parse an [RFC 2822] datetime string into a [`ZonedDateTime`].
124///
125/// This is a convenience function for using [`DateTimeParser`]. In particular,
126/// this takes a `&str` while the `DateTimeParser` accepts a `&[u8]`.
127/// Moreover, if any configuration options are added to RFC 2822 parsing (none
128/// currently exist at time of writing), then it will be necessary to use a
129/// `DateTimeParser` to toggle them. Additionally, a `DateTimeParser` is needed
130/// for parsing into a [`Timestamp`].
131///
132/// [RFC 2822]: https://datatracker.ietf.org/doc/html/rfc2822
133///
134/// # Warning
135///
136/// The RFC 2822 format only supports writing a precise instant in time
137/// expressed via a time zone offset. It does *not* support serializing
138/// the time zone itself. This means that if you format a zoned datetime
139/// in a time zone like `America/New_York` and then deserialize it, the
140/// zoned datetime you get back will be a "fixed offset" zoned datetime.
141/// This in turn means it will not perform daylight saving time safe
142/// arithmetic.
143///
144/// Basically, you should use the RFC 2822 format if it's required (for
145/// example, when dealing with email). But you should not choose it as a
146/// general interchange format for new applications.
147///
148/// # Errors
149///
150/// This returns an error if the datetime string given is invalid or if it
151/// is valid but doesn't fit in the datetime range supported by Jiff. For
152/// example, RFC 2822 supports offsets up to 99 hours and 59 minutes,
153/// but Jiff's maximum offset is 25 hours, 59 minutes and 59 seconds.
154///
155/// # Example
156///
157/// This example shows how serializing a zoned datetime to RFC 2822 format
158/// and then deserializing will drop information:
159///
160/// ```
161/// use jiff::{civil::date, fmt::rfc2822};
162///
163/// let zdt = date(2024, 7, 13)
164///     .at(15, 9, 59, 789_000_000)
165///     .in_tz("America/New_York")?;
166/// // The default format (i.e., Temporal) guarantees lossless
167/// // serialization.
168/// assert_eq!(zdt.to_string(), "2024-07-13T15:09:59.789-04:00[America/New_York]");
169///
170/// let rfc2822 = rfc2822::to_string(&zdt)?;
171/// // Notice that the time zone name and fractional seconds have been dropped!
172/// assert_eq!(rfc2822, "Sat, 13 Jul 2024 15:09:59 -0400");
173/// // And of course, if we parse it back, all that info is still lost.
174/// // Which means this `zdt` cannot do DST safe arithmetic!
175/// let zdt = rfc2822::parse(&rfc2822)?;
176/// assert_eq!(zdt.to_string(), "2024-07-13T15:09:59-04:00[-04:00]");
177///
178/// # Ok::<(), Box<dyn std::error::Error>>(())
179/// ```
180#[inline]
181pub fn parse(string: &str) -> Result<ZonedDateTime, Error> {
182    DEFAULT_DATETIME_PARSER.parse_zoned_datetime(string)
183}

240    /// When enabled, parsing will permit the weekday to be inconsistent with
241    /// the date. When enabled, the weekday is still parsed and can result in
242    /// an error if it isn't _a_ valid weekday. Only the error checking for
243    /// whether it is _the_ correct weekday for the parsed date is disabled.
244    ///
245    /// This is sometimes useful for interaction with systems that don't do
246    /// strict error checking.
247    ///
248    /// This is disabled by default. And note that RFC 2822 compliance requires
249    /// that the weekday is consistent with the date.
250    ///
251    /// # Example
252    ///
253    /// ```
254    /// use jiff::{civil::date, fmt::rfc2822};

257    /// // The above normally results in an error, since 2024-07-13 is a
258    /// // Saturday:
259    /// assert!(rfc2822::parse(string).is_err());
260    /// // But we can relax the error checking:
261    /// static P: rfc2822::DateTimeParser = rfc2822::DateTimeParser::new()
262    ///     .relaxed_weekday(true);

423    /// Parses a civil datetime from an RFC 2822 string. The input may have
424    /// leading whitespace.
425    ///
426    /// This also parses and trailing whitespace, including requiring at least
427    /// one whitespace character.
428    ///
429    /// This basically parses everything except for the zone.
430    #[cfg_attr(feature = "perf-inline", inline(always))]
431    fn parse_datetime<'i>(
432        &self,
433        input: &'i [u8],
434    ) -> Result<Parsed<'i, DateTime>, Error> {
435        if input.is_empty() {
436            return Err(Error::from(E::Empty));
437        }
438        let Parsed { input, .. } = self.skip_whitespace(input);
439        if input.is_empty() {
440            return Err(Error::from(E::EmptyAfterWhitespace));
441        }
442        let Parsed { value: wd, input } = self.parse_weekday(input)?;
443        let Parsed { value: day, input } = self.parse_day(input)?;
444        let Parsed { value: month, input } = self.parse_month(input)?;
445        let Parsed { value: year, input } = self.parse_year(input)?;
446
447        let Parsed { value: hour, input } = self.parse_hour(input)?;
448        let Parsed { input, .. } = self.skip_whitespace(input);
449        let Parsed { input, .. } = self.parse_time_separator(input)?;
450        let Parsed { input, .. } = self.skip_whitespace(input);
451        let Parsed { value: minute, input } = self.parse_minute(input)?;
452
453        let Parsed { value: whitespace_after_minute, input } =
454            self.skip_whitespace(input);
455        let (second, input) = if !input.starts_with(b":") {
456            if !whitespace_after_minute {
457                return Err(Error::from(E::WhitespaceAfterTime));
458            }
459            (0, input)
460        } else {
461            let Parsed { input, .. } = self.parse_time_separator(input)?;
462            let Parsed { input, .. } = self.skip_whitespace(input);
463            let Parsed { value: second, input } = self.parse_second(input)?;
464            let Parsed { input, .. } = self.parse_whitespace(input)?;
465            (second, input)
466        };
467
468        let date = Date::new(year, month, day).context(E::InvalidDate)?;
469        // OK because hour, minute and second have been verified as being
470        // in bounds. And all combinations of such in-bound values are also
471        // valid `Time` values.
472        let time = Time::new(hour, minute, second, 0).unwrap();
473        let dt = DateTime::from_parts(date, time);
474        if let Some(wd) = wd {
475            if !self.relaxed_weekday && wd != dt.weekday() {
476                return Err(Error::from(E::InconsistentWeekday {
477                    parsed: wd,
478                    from_date: dt.weekday(),
479                }));
480            }
481        }
482        Ok(Parsed { value: dt, input })
483    }

485    /// Parses an optional weekday at the beginning of an RFC 2822 datetime.
486    ///
487    /// This expects that any optional whitespace preceding the start of an
488    /// optional day has been stripped and that the input has at least one
489    /// byte.
490    ///
491    /// When the first byte of the given input is a digit (or is empty), then
492    /// this returns `None`, as it implies a day is not present. But if it
493    /// isn't a digit, then we assume that it must be a weekday and return an
494    /// error based on that assumption if we couldn't recognize a weekday.
495    ///
496    /// If a weekday is parsed, then this also skips any trailing whitespace
497    /// (and requires at least one whitespace character).
498    #[cfg_attr(feature = "perf-inline", inline(always))]
499    fn parse_weekday<'i>(
500        &self,
501        input: &'i [u8],
502    ) -> Result<Parsed<'i, Option<Weekday>>, Error> {
503        // An empty input is invalid, but we let that case be
504        // handled by the caller. Otherwise, we know there MUST
505        // be a present day if the first character isn't an ASCII
506        // digit.
507        if #[allow(non_exhaustive_omitted_patterns)] match input[0] {
    b'0'..=b'9' => true,
    _ => false,
}matches!(input[0], b'0'..=b'9') {
508            return Ok(Parsed { value: None, input });
509        }
510        if let Ok(len) = u8::try_from(input.len()) {
511            if len < 4 {
512                return Err(Error::from(E::TooShortWeekday {
513                    got_non_digit: input[0],
514                    len,
515                }));
516            }
517        }
518        let b1 = input[0];
519        let b2 = input[1];
520        let b3 = input[2];
521        let wd = match &[
522            b1.to_ascii_lowercase(),
523            b2.to_ascii_lowercase(),
524            b3.to_ascii_lowercase(),
525        ] {
526            b"sun" => Weekday::Sunday,
527            b"mon" => Weekday::Monday,
528            b"tue" => Weekday::Tuesday,
529            b"wed" => Weekday::Wednesday,
530            b"thu" => Weekday::Thursday,
531            b"fri" => Weekday::Friday,
532            b"sat" => Weekday::Saturday,
533            _ => {
534                return Err(Error::from(E::InvalidWeekday {
535                    got_non_digit: input[0],
536                }));
537            }
538        };
539        let Parsed { input, .. } = self.skip_whitespace(&input[3..]);
540        let Some(should_be_comma) = input.get(0).copied() else {
541            return Err(Error::from(E::EndOfInputComma));
542        };
543        if should_be_comma != b',' {
544            return Err(Error::from(E::UnexpectedByteComma {
545                byte: should_be_comma,
546            }));
547        }
548        let Parsed { input, .. } = self.skip_whitespace(&input[1..]);
549        Ok(Parsed { value: Some(wd), input })
550    }

552    /// Parses a 1 or 2 digit day.
553    ///
554    /// This assumes the input starts with what must be an ASCII digit (or it
555    /// may be empty).
556    ///
557    /// This also parses at least one mandatory whitespace character after the
558    /// day.
559    #[cfg_attr(feature = "perf-inline", inline(always))]
560    fn parse_day<'i>(&self, input: &'i [u8]) -> Result<Parsed<'i, i8>, Error> {
561        if input.is_empty() {
562            return Err(Error::from(E::EndOfInputDay));
563        }
564        let mut digits = 1;
565        if input.len() >= 2 && #[allow(non_exhaustive_omitted_patterns)] match input[1] {
    b'0'..=b'9' => true,
    _ => false,
}matches!(input[1], b'0'..=b'9') {
566            digits = 2;
567        }
568        let (day, input) = input.split_at(digits);
569        let day = parse::bi64::<b::Day>(day).context(E::ParseDay)?;
570        let Parsed { input, .. } =
571            self.parse_whitespace(input).context(E::WhitespaceAfterDay)?;
572        Ok(Parsed { value: day, input })
573    }

583    fn parse_month<'i>(
584        &self,
585        input: &'i [u8],
586    ) -> Result<Parsed<'i, i8>, Error> {
587        if input.is_empty() {
588            return Err(Error::from(E::EndOfInputMonth));
589        }
590        if let Ok(len) = u8::try_from(input.len()) {
591            if len < 3 {
592                return Err(Error::from(E::TooShortMonth { len }));
593            }
594        }
595        let b1 = input[0].to_ascii_lowercase();
596        let b2 = input[1].to_ascii_lowercase();
597        let b3 = input[2].to_ascii_lowercase();
598        let month = match &[b1, b2, b3] {
599            b"jan" => 1,
600            b"feb" => 2,
601            b"mar" => 3,
602            b"apr" => 4,
603            b"may" => 5,
604            b"jun" => 6,
605            b"jul" => 7,
606            b"aug" => 8,
607            b"sep" => 9,
608            b"oct" => 10,
609            b"nov" => 11,
610            b"dec" => 12,
611            _ => return Err(Error::from(E::InvalidMonth)),
612        };

614            .parse_whitespace(&input[3..])
615            .context(E::WhitespaceAfterMonth)?;

617    }

619    /// Parses a 2, 3 or 4 digit year.
620    ///
621    /// This assumes the input starts with what must be an ASCII digit (or it
622    /// may be empty).
623    ///
624    /// This also parses at least one mandatory whitespace character after the
625    /// day.
626    ///
627    /// The 2 or 3 digit years are "obsolete," which we support by following
628    /// the rules in RFC 2822:
629    ///
630    /// > Where a two or three digit year occurs in a date, the year is to be
631    /// > interpreted as follows: If a two digit year is encountered whose
632    /// > value is between 00 and 49, the year is interpreted by adding 2000,
633    /// > ending up with a value between 2000 and 2049. If a two digit year is
634    /// > encountered with a value between 50 and 99, or any three digit year
635    /// > is encountered, the year is interpreted by adding 1900.
636    #[cfg_attr(feature = "perf-inline", inline(always))]
637    fn parse_year<'i>(
638        &self,
639        input: &'i [u8],
640    ) -> Result<Parsed<'i, i16>, Error> {
641        let mut digits = 0;
642        while digits <= 3
643            && !input[digits..].is_empty()
644            && #[allow(non_exhaustive_omitted_patterns)] match input[digits] {
    b'0'..=b'9' => true,
    _ => false,
}matches!(input[digits], b'0'..=b'9')
645        {
646            digits += 1;
647        }
648        if let Ok(len) = u8::try_from(digits) {
649            if len <= 1 {
650                return Err(Error::from(E::TooShortYear { len }));
651            }
652        }
653        let (year, input) = input.split_at(digits);
654        let year = parse::bi64::<b::Year>(year).context(E::ParseYear)?;
655        let year = match digits {
656            2 if year <= 49 => year + 2000,
657            2 | 3 => year + 1900,
658            4 => year,
659            _ => {
    ::core::panicking::panic_fmt(format_args!("internal error: entered unreachable code: {0}",
            format_args!("digits={0} must be 2, 3 or 4", digits)));
}unreachable!("digits={digits} must be 2, 3 or 4"),
660        };
661        let Parsed { input, .. } =
662            self.parse_whitespace(input).context(E::WhitespaceAfterYear)?;
663        Ok(Parsed { value: year, input })
664    }

712    /// Parses a time zone offset (including obsolete offsets like EDT).
713    ///
714    /// This assumes the offset must begin at the beginning of `input`. That
715    /// is, any leading whitespace should already have been trimmed.
716    #[cfg_attr(feature = "perf-inline", inline(always))]
717    fn parse_offset<'i>(
718        &self,
719        input: &'i [u8],
720    ) -> Result<Parsed<'i, Offset>, Error> {
721        let sign = input.get(0).copied().ok_or(E::EndOfInputOffset)?;
722        let sign = if sign == b'+' {
723            Sign::Positive
724        } else if sign == b'-' {
725            Sign::Negative
726        } else {
727            return self.parse_offset_obsolete(input);
728        };
729        let input = &input[1..];
730        let (hhmm, input) = parse::split(input, 4).ok_or(E::TooShortOffset)?;
731
732        let hh = parse::bi64::<b::OffsetHours>(&hhmm[0..2])
733            .context(E::ParseOffsetHour)?;
734        let mm = parse::bi64::<b::OffsetMinutes>(&hhmm[2..4])
735            .context(E::ParseOffsetMinute)?;
736
737        let seconds = sign * (i32::from(hh) * 3_600 + i32::from(mm) * 60);
738        // OK because we check the bounds of both hours and minutes.
739        let offset = Offset::from_seconds(seconds).unwrap();
740        Ok(Parsed { value: offset, input })
741    }

743    /// Parses an obsolete time zone offset.
744    #[inline(never)]
745    fn parse_offset_obsolete<'i>(
746        &self,
747        input: &'i [u8],
748    ) -> Result<Parsed<'i, Offset>, Error> {
749        let mut letters = [0; 5];
750        let mut len = 0;
751        while len <= 4
752            && !input[len..].is_empty()
753            && !is_whitespace(input[len])
754        {
755            letters[len] = input[len].to_ascii_lowercase();
756            len += 1;
757        }
758        if len == 0 {
759            return Err(Error::from(E::WhitespaceAfterTimeForObsoleteOffset));
760        }
761        let offset = match &letters[..len] {
762            b"ut" | b"gmt" | b"z" => Offset::UTC,
763            b"est" => Offset::constant(-5),
764            b"edt" => Offset::constant(-4),
765            b"cst" => Offset::constant(-6),
766            b"cdt" => Offset::constant(-5),
767            b"mst" => Offset::constant(-7),
768            b"mdt" => Offset::constant(-6),
769            b"pst" => Offset::constant(-8),
770            b"pdt" => Offset::constant(-7),
771            name => {
772                if name.len() == 1
773                    && #[allow(non_exhaustive_omitted_patterns)] match name[0] {
    b'a'..=b'i' | b'k'..=b'z' => true,
    _ => false,
}matches!(name[0], b'a'..=b'i' | b'k'..=b'z')
774                {
775                    // Section 4.3 indicates these as military time:
776                    //
777                    // > The 1 character military time zones were defined in
778                    // > a non-standard way in [RFC822] and are therefore
779                    // > unpredictable in their meaning. The original
780                    // > definitions of the military zones "A" through "I" are
781                    // > equivalent to "+0100" through "+0900" respectively;
782                    // > "K", "L", and "M" are equivalent to "+1000", "+1100",
783                    // > and "+1200" respectively; "N" through "Y" are
784                    // > equivalent to "-0100" through "-1200" respectively;
785                    // > and "Z" is equivalent to "+0000". However, because of
786                    // > the error in [RFC822], they SHOULD all be considered
787                    // > equivalent to "-0000" unless there is out-of-band
788                    // > information confirming their meaning.
789                    //
790                    // So just treat them as UTC.
791                    Offset::UTC
792                } else if name.len() >= 3
793                    && name.iter().all(|&b| #[allow(non_exhaustive_omitted_patterns)] match b {
    b'a'..=b'z' => true,
    _ => false,
}matches!(b, b'a'..=b'z'))
794                {
795                    // Section 4.3 also says that anything that _looks_ like a
796                    // zone name should just be -0000 too:
797                    //
798                    // > Other multi-character (usually between 3 and 5)
799                    // > alphabetic time zones have been used in Internet
800                    // > messages. Any such time zone whose meaning is not
801                    // > known SHOULD be considered equivalent to "-0000"
802                    // > unless there is out-of-band information confirming
803                    // > their meaning.
804                    Offset::UTC
805                } else {
806                    // But anything else we throw our hands up I guess.
807                    return Err(Error::from(E::InvalidObsoleteOffset));
808                }
809            }
810        };
811        Ok(Parsed { value: offset, input: &input[len..] })
812    }

832    /// Parses at least one whitespace character. If no whitespace was found,
833    /// then this returns an error.

837        input: &'i [u8],

847    /// Skips over any ASCII whitespace at the beginning of `input`.
848    ///
849    /// This returns the input unchanged if it does not begin with whitespace.
850    /// The resulting value is `true` if any whitespace was consumed,
851    /// and `false` if none was.
852    #[cfg_attr(feature = "perf-inline", inline(always))]
853    fn skip_whitespace<'i>(&self, mut input: &'i [u8]) -> Parsed<'i, bool> {
854        let mut found_whitespace = false;
855        while input.first().map_or(false, |&b| is_whitespace(b)) {
856            input = &input[1..];
857            found_whitespace = true;
858        }
859        Parsed { value: found_whitespace, input }
860    }

862    /// This attempts to parse and skip any trailing "comment" in an RFC 2822
863    /// datetime.
864    ///
865    /// This is a bit more relaxed than what RFC 2822 specifies. We basically
866    /// just try to balance parenthesis and skip over escapes.
867    ///
868    /// This assumes that if a comment exists, its opening parenthesis is at
869    /// the beginning of `input`. That is, any leading whitespace has been
870    /// stripped.
871    #[inline(never)]
872    fn skip_comment<'i>(
873        &self,
874        mut input: &'i [u8],
875    ) -> Result<Parsed<'i, ()>, Error> {
876        if !input.starts_with(b"(") {
877            return Ok(Parsed { value: (), input });
878        }
879        input = &input[1..];
880        let mut depth: u8 = 1;
881        let mut escape = false;
882        for byte in input.iter().copied() {
883            input = &input[1..];
884            if escape {
885                escape = false;
886            } else if byte == b'\\' {
887                escape = true;
888            } else if byte == b')' {
889                // I believe this error case is actually impossible, since as
890                // soon as we hit 0, we break out. If there is more "comment,"
891                // then it will flag an error as unparsed input.
892                depth = depth
893                    .checked_sub(1)
894                    .ok_or(E::CommentClosingParenWithoutOpen)?;
895                if depth == 0 {
896                    break;
897                }
898            } else if byte == b'(' {
899                depth = depth
900                    .checked_add(1)
901                    .ok_or(E::CommentTooManyNestedParens)?;
902            }
903        }
904        if depth > 0 {
905            return Err(Error::from(E::CommentOpeningParenWithoutClose));
906        }
907        let Parsed { input, .. } = self.skip_whitespace(input);
908        Ok(Parsed { value: (), input })
909    }

912/// A printer for [RFC 2822] datetimes.
913///
914/// This printer converts an in memory representation of a precise instant in
915/// time to an RFC 2822 formatted string. That is, [`ZonedDateTime`] or
916/// [`Timestamp`], since all other datetime types in Jiff are inexact.
917///
918/// [RFC 2822]: https://datatracker.ietf.org/doc/html/rfc2822
919///
920/// # Warning
921///
922/// The RFC 2822 format only supports writing a precise instant in time
923/// expressed via a time zone offset. It does *not* support serializing
924/// the time zone itself. This means that if you format a zoned datetime
925/// in a time zone like `America/New_York` and then deserialize it, the
926/// zoned datetime you get back will be a "fixed offset" zoned datetime.
927/// This in turn means it will not perform daylight saving time safe
928/// arithmetic.
929///
930/// Basically, you should use the RFC 2822 format if it's required (for
931/// example, when dealing with email). But you should not choose it as a
932/// general interchange format for new applications.
933///
934/// # Example
935///
936/// This example shows how to convert a zoned datetime to the RFC 2822 format:
937///
938/// ```
939/// use jiff::{civil::date, fmt::rfc2822::DateTimePrinter};
940///
941/// const PRINTER: DateTimePrinter = DateTimePrinter::new();
942///
943/// let zdt = date(2024, 6, 15).at(7, 0, 0, 0).in_tz("Australia/Hobart")?;
944///
945/// let mut buf = String::new();
946/// PRINTER.print_zoned_datetime(&zdt, &mut buf)?;
947/// assert_eq!(buf, "Sat, 15 Jun 2024 07:00:00 +1000");
948///
949/// # Ok::<(), Box<dyn std::error::Error>>(())
950/// ```
951///
952/// # Example: using adapters with `std::io::Write` and `std::fmt::Write`
953///
954/// By using the [`StdIoWrite`](super::StdIoWrite) and
955/// [`StdFmtWrite`](super::StdFmtWrite) adapters, one can print datetimes
956/// directly to implementations of `std::io::Write` and `std::fmt::Write`,
957/// respectively. The example below demonstrates writing to anything
958/// that implements `std::io::Write`. Similar code can be written for
959/// `std::fmt::Write`.
960///
961/// ```no_run
962/// use std::{fs::File, io::{BufWriter, Write}, path::Path};
963///
964/// use jiff::{civil::date, fmt::{StdIoWrite, rfc2822::DateTimePrinter}};
965///
966/// let zdt = date(2024, 6, 15).at(7, 0, 0, 0).in_tz("Asia/Kolkata")?;
967///
968/// let path = Path::new("/tmp/output");
969/// let mut file = BufWriter::new(File::create(path)?);
970/// DateTimePrinter::new()
971///     .print_zoned_datetime(&zdt, StdIoWrite(&mut file))
972///     .unwrap();
973/// file.flush()?;
974/// assert_eq!(
975///     std::fs::read_to_string(path)?,
976///     "Sat, 15 Jun 2024 07:00:00 +0530",
977/// );
978///
979/// # Ok::<(), Box<dyn std::error::Error>>(())
980/// ```

1150    /// [`ZonedDateTime::timestamp`].
1151    ///
1152    /// Moreover, since RFC 2822 does not support fractional seconds, this
1153    /// routine prints the zoned datetime as if truncating any fractional
1154    /// seconds.
1155    ///
1156    /// # Warning
1157    ///
1158    /// The RFC 2822 format only supports writing a precise instant in time
1159    /// expressed via a time zone offset. It does *not* support serializing
1160    /// the time zone itself. This means that if you format a zoned datetime
1161    /// in a time zone like `America/New_York` and then deserialize it, the
1162    /// zoned datetime you get back will be a "fixed offset" zoned datetime.
1163    /// This in turn means it will not perform daylight saving time safe
1164    /// arithmetic.
1165    ///
1166    /// Basically, you should use the RFC 2822 format if it's required (for
1167    /// example, when dealing with email). But you should not choose it as a
1168    /// general interchange format for new applications.
1169    ///
1170    /// # Errors
1171    ///
1172    /// This returns an error when writing to the given [`Write`]
1173    /// implementation would fail. Some such implementations, like for `String`
1174    /// and `Vec<u8>`, never fail (unless memory allocation fails).
1175    ///
1176    /// This can also return an error if the year corresponding to this
1177    /// timestamp cannot be represented in the RFC 2822 format. For example, a
1178    /// negative year.
1179    ///
1180    /// # Example
1181    ///
1182    /// ```
1183    /// use jiff::{civil::date, fmt::rfc2822::DateTimePrinter};
1184    ///
1185    /// const PRINTER: DateTimePrinter = DateTimePrinter::new();
1186    ///
1187    /// let zdt = date(2024, 6, 15).at(7, 0, 0, 0).in_tz("America/New_York")?;
1188    ///
1189    /// let mut buf = String::new();
1190    /// PRINTER.print_zoned_datetime(&zdt, &mut buf)?;
1191    /// assert_eq!(buf, "Sat, 15 Jun 2024 07:00:00 -0400");
1192    ///
1193    /// # Ok::<(), Box<dyn std::error::Error>>(())
1194    /// ```
1195    pub fn print_zoned_datetime<W: Write>(
1196        &self,
1197        zdt: &ZonedDateTime,
1198        mut wtr: W,
1199    ) -> Result<(), Error> {
1200        BorrowedBuffer::with_writer::<PRINTER_MAX_BYTES_RFC2822>(
1201            &mut wtr,
1202            PRINTER_MAX_BYTES_RFC2822,
1203            |bbuf| {
1204                self.print_civil_with_offset(
1205                    zdt.datetime(),
1206                    Some(zdt.offset()),
1207                    bbuf,
1208                )
1209            },
1210        )
1211    }

1214    ///
1215    /// This always emits `-0000` as the offset in the RFC 2822 format. If you
1216    /// desire a `+0000` offset, use [`DateTimePrinter::print_zoned_datetime`]
1217    /// with a zoned datetime with [`TimeZone::UTC`].
1218    ///
1219    /// Moreover, since RFC 2822 does not support fractional seconds, this
1220    /// routine prints the timestamp as if truncating any fractional seconds.
1221    ///
1222    /// # Errors
1223    ///
1224    /// This returns an error when writing to the given [`Write`]
1225    /// implementation would fail. Some such implementations, like for `String`
1226    /// and `Vec<u8>`, never fail (unless memory allocation fails).
1227    ///
1228    /// This can also return an error if the year corresponding to this
1229    /// timestamp cannot be represented in the RFC 2822 format. For example, a
1230    /// negative year.
1231    ///
1232    /// # Example
1233    ///
1234    /// ```
1235    /// use jiff::{fmt::rfc2822::DateTimePrinter, Timestamp};
1236    ///
1237    /// let timestamp = Timestamp::from_second(1)
1238    ///     .expect("one second after Unix epoch is always valid");
1239    ///
1240    /// let mut buf = String::new();
1241    /// DateTimePrinter::new().print_timestamp(&timestamp, &mut buf)?;
1242    /// assert_eq!(buf, "Thu, 1 Jan 1970 00:00:01 -0000");
1243    ///
1244    /// # Ok::<(), Box<dyn std::error::Error>>(())
1245    /// ```
1246    pub fn print_timestamp<W: Write>(
1247        &self,
1248        timestamp: &Timestamp,
1249        mut wtr: W,
1250    ) -> Result<(), Error> {

1252        BorrowedBuffer::with_writer::<PRINTER_MAX_BYTES_RFC2822>(
1253            &mut wtr,
1254            PRINTER_MAX_BYTES_RFC2822,

1259    /// Print a `Timestamp` datetime to the given writer in a way that is
1260    /// explicitly compatible with [RFC 9110]. This is typically useful in
1261    /// contexts where strict compatibility with HTTP is desired.
1262    ///
1263    /// This always emits `GMT` as the offset and always uses two digits for
1264    /// the day. This results in a fixed length format that always uses 29
1265    /// characters.
1266    ///
1267    /// Since neither RFC 2822 nor RFC 9110 supports fractional seconds, this
1268    /// routine prints the timestamp as if truncating any fractional seconds.
1269    ///
1270    /// # Errors
1271    ///
1272    /// This returns an error when writing to the given [`Write`]
1273    /// implementation would fail. Some such implementations, like for `String`
1274    /// and `Vec<u8>`, never fail (unless memory allocation fails).
1275    ///
1276    /// This can also return an error if the year corresponding to this
1277    /// timestamp cannot be represented in the RFC 2822 or RFC 9110 format. For
1278    /// example, a negative year.
1279    ///
1280    /// # Example
1281    ///
1282    /// ```
1283    /// use jiff::{fmt::rfc2822::DateTimePrinter, Timestamp};
1284    ///
1285    /// let timestamp = Timestamp::from_second(1)
1286    ///     .expect("one second after Unix epoch is always valid");
1287    ///
1288    /// let mut buf = String::new();
1289    /// DateTimePrinter::new().print_timestamp_rfc9110(&timestamp, &mut buf)?;
1290    /// assert_eq!(buf, "Thu, 01 Jan 1970 00:00:01 GMT");
1291    ///
1292    /// # Ok::<(), Box<dyn std::error::Error>>(())
1293    /// ```
1294    ///
1295    /// [RFC 9110]: https://datatracker.ietf.org/doc/html/rfc9110#section-5.6.7-15
1296    pub fn print_timestamp_rfc9110<W: Write>(
1297        &self,
1298        timestamp: &Timestamp,
1299        mut wtr: W,
1300    ) -> Result<(), Error> {
1301        let dt = TimeZone::UTC.to_datetime(*timestamp);
1302        BorrowedBuffer::with_writer::<PRINTER_MAX_BYTES_RFC9110>(
1303            &mut wtr,
1304            PRINTER_MAX_BYTES_RFC9110,
1305            |bbuf| self.print_civil_always_utc(dt, bbuf),
1306        )
1307    }

1309    #[inline(never)]
1310    fn print_civil_with_offset(
1311        &self,
1312        dt: DateTime,
1313        offset: Option<Offset>,
1314        buf: &mut BorrowedBuffer<'_>,
1315    ) -> Result<(), Error> {
1316        if dt.year() < 0 {
1317            // RFC 2822 actually says the year must be at least 1900, but
1318            // other implementations (like Chrono) allow any positive 4-digit
1319            // year.
1320            return Err(Error::from(E::NegativeYear));
1321        }
1322
1323        buf.write_str(weekday_abbrev(dt.weekday()));
1324        buf.write_str(", ");
1325        buf.write_int(dt.day().unsigned_abs());
1326        buf.write_ascii_char(b' ');
1327        buf.write_str(month_name(dt.month()));
1328        buf.write_ascii_char(b' ');
1329        buf.write_int_pad4(dt.year().unsigned_abs());
1330        buf.write_ascii_char(b' ');
1331        buf.write_int_pad2(dt.hour().unsigned_abs());
1332        buf.write_ascii_char(b':');
1333        buf.write_int_pad2(dt.minute().unsigned_abs());
1334        buf.write_ascii_char(b':');
1335        buf.write_int_pad2(dt.second().unsigned_abs());
1336        buf.write_ascii_char(b' ');
1337
1338        let Some(offset) = offset else {
1339            buf.write_str("-0000");
1340            return Ok(());
1341        };
1342        buf.write_ascii_char(if offset.is_negative() { b'-' } else { b'+' });
1343        let (offset_hours, offset_minutes) = offset.round_to_nearest_minute();
1344        buf.write_int_pad2(offset_hours);
1345        buf.write_int_pad2(offset_minutes);
1346
1347        Ok(())
1348    }

1351    fn print_civil_always_utc(
1352        &self,
1353        dt: DateTime,
1354        buf: &mut BorrowedBuffer<'_>,
1355    ) -> Result<(), Error> {
1356        if dt.year() < 0 {
1357            // RFC 2822 actually says the year must be at least 1900, but
1358            // other implementations (like Chrono) allow any positive 4-digit
1359            // year.
1360            return Err(Error::from(E::NegativeYear));
1361        }
1362
1363        buf.write_str(weekday_abbrev(dt.weekday()));
1364        buf.write_str(", ");
1365        buf.write_int_pad2(dt.day().unsigned_abs());
1366        buf.write_str(" ");
1367        buf.write_str(month_name(dt.month()));
1368        buf.write_str(" ");
1369        buf.write_int_pad4(dt.year().unsigned_abs());
1370        buf.write_str(" ");
1371        buf.write_int_pad2(dt.hour().unsigned_abs());
1372        buf.write_str(":");
1373        buf.write_int_pad2(dt.minute().unsigned_abs());
1374        buf.write_str(":");
1375        buf.write_int_pad2(dt.second().unsigned_abs());
1376        buf.write_str(" ");
1377        buf.write_str("GMT");
1378        Ok(())
1379    }

1412/// Returns true if the given byte is "whitespace" as defined by RFC 2822.
1413///
1414/// From S2.2.2:
1415///
1416/// > Many of these tokens are allowed (according to their syntax) to be
1417/// > introduced or end with comments (as described in section 3.2.3) as well
1418/// > as the space (SP, ASCII value 32) and horizontal tab (HTAB, ASCII value
1419/// > 9) characters (together known as the white space characters, WSP), and
1420/// > those WSP characters are subject to header "folding" and "unfolding" as
1421/// > described in section 2.2.3.
1422///
1423/// In other words, ASCII space or tab.
1424///
1425/// With all that said, it seems odd to limit this to just spaces or tabs, so
1426/// we relax this and let it absorb any kind of ASCII whitespace. This also
1427/// handles, I believe, most cases of "folding" whitespace. (By treating `\r`
1428/// and `\n` as whitespace.)
1429fn is_whitespace(byte: u8) -> bool {
1430    byte.is_ascii_whitespace()
1431}

1864    fn ok_minimum_offset_roundtrip() {
1865        let zdt = date(2025, 12, 25)
1866            .at(17, 0, 0, 0)
1867            .to_zoned_datetime(TimeZone::fixed(Offset::MIN))
1868            .unwrap();
1869        let string =
1870            DateTimePrinter::new().zoned_datetime_to_string(&zdt).unwrap();
1871        assert_eq!(string, "Thu, 25 Dec 2025 17:00:00 -2559");
1872
1873        let got: ZonedDateTime =
1874            DateTimeParser::new().parse_zoned_datetime(&string).unwrap();
1875        // Since we started with a zoned datetime with a minimal offset
1876        // (to second precision) and RFC 2822 only supports minute precision
1877        // in time zone offsets, printing the zoned datetime rounds the offset.
1878        // But this would normally result in an offset beyond Jiff's limits,
1879        // so in this case, the offset truncates to the minimum supported
1880        // value by both Jiff and RFC 2822. That's what we test for here.
1881        let expected = date(2025, 12, 25)
1882            .at(17, 0, 0, 0)
1883            .to_zoned_datetime(TimeZone::fixed(-Offset::hms(25, 59, 0)))
1884            .unwrap();
1885        assert_eq!(expected, got);
1886    }
